## Findings

- **[severity: bug (doc numeric)]** extras/mainflow_tree/README.md:171-174. This text sits inside the diff's hunk but was not updated, and it now contradicts both the measurement and the research rewrite in the same diff. "shifted to small coordinates, both cm segments' errors go away" is false for each shift that was tried. findings.md "Evidence: the shift test" says the integer offset took USKE 4->0 and MSKE 4->**1**, and the bbox corner took MSKE 4->0 and USKE 4->**1**. The research diff now says so correctly at research/fwa_mainflow_tree.md:37 ("two shifts each left one error in one group"). Fix: say that a shift removed one group's errors and left one error in the other, and give 9 mm (or ~1 cm) at 10⁵ m. Or drop the magnitude and point to research.

- **[severity: fragile]** extras/mainflow_tree/ssnbler_check.R:26-27. The "local" label is a proxy that does not separate the cases it reports on. A CRAN install made with `install.packages()` has no `RemoteSha`, so it prints `ssnbler: 1.1.2 local`. I measured this: a temp-lib CRAN 1.1.2 printed exactly that. A pak install from CRAN has `RemoteSha` equal to the version (sf, dplyr and jsonlite show `RemoteType: standard, RemoteSha: <version>`), so it prints `ssnbler: 1.1.2 1.1.2`. Neither is a local build. In the other direction, a local install of unfixed upstream `develop` (also 1.1.2.9000) prints the same `1.1.2.9000 local` as the local fork build the whole-Skeena run recorded in runs.log. The version still separates CRAN from the fork, so nothing fails today. But the README says the script prints "the SSNbler build it ran", and for the headline Skeena run the runs.log line cannot say which tree it was. Fix if wanted: print `RemoteType`, and the sha only when `RemoteType` is `github`. For a source install, record the commit separately, as the README already does.

- **[severity: fragile]** extras/mainflow_tree/README.md:184-190. "Re-run on the fork at 37ca338 (2026-10-11)" covers the Bulkley bullet, but runs.log shows the Bulkley ran on the local build (`ssnbler: 1.1.2.9000 local`, 2026-10-10 23:24), the same 8505fb5 tree as the Skeena. Only the Skeena bullet carries the "one wording commit before 37ca338" caveat. The R code is identical, so the result stands, but the provenance as written is wrong for that bullet. Move the caveat to the heading, or add it to the Bulkley bullet too.

- **[severity: fragile]** extras/mainflow_tree/ssnbler_check.sh:182-185. runs.log records `node errors: N  outlets: M` and the build, but not the new `relationships:` line. The per-run log has the line. The README says runs.log carries the "result". If runs.log is meant to be the record, extract `relationships: [0-9]*  expected: [0-9]*  edges into two: [0-9]*` the same way as `result`.
