- **[severity: fragile]** extras/mainflow_tree/article/sql/confluence_share.sql:810-812 and article_extract.sh:5. The header promises "a re-extract of the same build writes the same files". But `sum(i.upstream_area_ha)` and `sum(il.upstream_area_ha)` add their inflows in whatever order the join and aggregate deliver them. A parallel or re-planned run can change the last bits of `share_tree` and `share_lookup`, which `\copy` writes at full precision, so confluence_share.csv can churn with no data change. `sum(i.upstream_area_ha ORDER BY i.linear_feature_id)` (and the same for `il`) fixes the order.   - **Rule:** code-check-r.md "Postgres row order is never fixed unless the query fixes it, so a pick, a float sum and a presence check can each depend on it".
